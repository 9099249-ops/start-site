# Безопасная разработка СТАРТа

## Как теперь работать

Задача → отдельная ветка → изменения → тесты → commit → push → Pull Request
→ независимая проверка → решение владельца → merge человеком.

Основная ветка: `main`. GitHub: https://github.com/9099249-ops/start-site.
Merge не публикует сайт. Выпуск на сервер и Raspberry Pi всегда отдельный.

## Файлы процесса

- AGENTS.md: обязательные ветки, PR, независимое review и запрет auto-merge.
- CONTRIBUTING.md: подготовка, команды, commit/push, проверки и выпуск.
- .github/pull_request_template.md: описание, проверки, риски и ручные сценарии.
- .github/workflows/checks.yml: автоматические проверки PR и main.
- .githooks/pre-commit и pre-push: локальная защита основной ветки.

У обычного сайта нет отдельной сборки, линтера и typecheck. Для игры build
включает TypeScript. Отсутствие инструмента не означает, что он «пройден».
Результат CI не заменяет проверку бизнес-логики и мобильного интерфейса.

Имена проверок для защиты main: `server-tests`, `print-agent-tests`, `game-checks`.
Actions закреплены по SHA, токен только `contents: read`, checkout не сохраняет
учётные данные. Секреты сервера не используются и не загружаются.

## Code Review в Codex

Официальная инструкция: https://learn.chatgpt.com/docs/third-party/github.
Для репозитория нужен включённый Code Review в настройках Codex. После создания
PR оставить комментарий `@codex review`; автоматические проверки можно включить
там же отдельно. Убедиться, что появился настоящий ответ проверяющего.
Создание PR само по себе не подтверждает, что ревью запущено или завершено.

Раздел Code Review зависит от подключения GitHub к конкретному аккаунту Codex.
Если PR там не виден, выбрать start-site в настройках Code Review и проверить
разрешения GitHub-приложения. Прикрепление PR к задаче в приложении не заменяет
включение облачного Code Review. Агент не создаёт фиктивное одобрение и не
одобряет собственный PR от имени владельца.

## Рекомендуемая защита main

До отдельного подтверждения владельца настройки GitHub не изменяются.
В GitHub → Settings → Rules → Rulesets (или Branches) для main рекомендуется:

1. Require a pull request before merging.
2. Запретить force push и удаление main.
3. Require conversation resolution.
4. Require status checks с точными именами новых CI-проверок после первого запуска.
5. Не давать агенту/bot bypass и не включать auto-merge.
6. При наличии второго человека — требовать его approval и сбрасывать старое
   approval при новых commits. Владелец не может одобрить собственный PR;
   единственному владельцу нельзя обещать такой процесс без второго reviewer.

Автоматический ответ Codex не равен обязательному человеческому approval.
Правила AGENTS и локальные hooks не заменяют серверную защиту GitHub.

## Что не делалось

Никакого merge, production deploy, изменения рабочих баз, env, DNS или hosting.
Установка защиты main и автоматического облачного Code Review не считается
завершённой, пока это не подтверждено реальными настройками/ответом сервиса.
