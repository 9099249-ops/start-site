# Кафе СТАРТ — локальный агент печати

Python 3 + CUPS + SQLite. Два типа документов: cafe_order и shift_report.
Шаблоны — examples/order.json и examples/shift-report.json. Отчёт получает готовые
суммы от сайта: дата, общий итог кассы (кафе + прокат), получатели и суммы переводов
только за текущую или последнюю кассовую смену. Уже выплаченное вычтено на сайте.
Агент не рассчитывает выручку и не выполняет переводы денег.

## Текущее ограничение

Принтер ещё не обнаружен. printing_enabled=false. Очередь start-kitchen — планируемое
имя, до подключения принтера она не создаётся. Бумажная печать, ширина и звуковой
сигнал должны быть проверены на реальном POScenter RP-100USE. Шаблон ESC/POS
использует монохромный растр 576 точек и DejaVu Sans с кириллицей, без зависимости
от кодовых страниц принтера. beep_hex пока пустой, команда звука требует проверки.
IP Raspberry Pi не меняется.

## Управление на Raspberry Pi

```sh
sudo start-print health
sudo start-print jobs
sudo start-print submit /opt/start-print-agent/examples/order.json
sudo start-print submit /opt/start-print-agent/examples/shift-report.json
sudo start-print reprint TEST-002
sudo start-print reprint TEST-SHIFT-001-v1 --type shift_report
systemctl status start-print-agent
sudo tail -n 100 /var/log/start-print-agent/agent.log
sudo journalctl -u start-print-agent -n 100 --no-pager
sudo systemctl restart start-print-agent
```

Повторная submit того же ID с теми же данными возвращает существующее задание.
Изменённые данные с тем же ID отклоняются; для новой редакции отчёта нужен новый
report_id. reprint создаёт отдельную попытку с пометкой ПОВТОР, только когда прежняя
завершена или признана ошибочной и в CUPS нет её активного задания.

## Надёжность

SQLite /var/lib/start-print-agent/queue.sqlite3 хранит документы и все попытки.
Статусы: received, printing, printed, failed. Дедупликация по (type, ID).
CUPS-задание создаётся удержанным: ID записывается на диск, документ загружается,
факт отправки сохраняется, затем снимается удержание. Сбой в неопределённый момент
оставляет failed/удержанное задание для ручной проверки. Автоматического повторного
создания такого задания нет. Сначала осмотрите бумагу и старое задание CUPS;
при необходимости отмените именно его, затем выполните reprint.

printed означает «CUPS завершил передачу», а не доказательство выхода бумаги.
Абсолютная гарантия ровно одного физического чека невозможна при обрыве питания/
USB без подтверждения от принтера. CUPS error policy при настройке очереди должна
быть stop-printer, чтобы не повторять неоднозначную передачу автоматически.
Полученные задания сохраняются без интернета. Неполученные задания обязан хранить
сервер сайта. Лимит ожидающей очереди 10000; при заполнении сервер должен повторить
доставку позже. База дедупликации намеренно не очищается автоматически.
Файловые логи: 5 файлов максимум по 2 МиБ, без токенов и содержимого заказов.

## Локальный REST API

Сервис слушает только 127.0.0.1:8765. Все запросы требуют
Authorization: Bearer <api_token из защищённого config.json>.
GET /health, GET /jobs; POST /jobs — JSON заказа/отчёта;
POST /reprint — {"type":"cafe_order","id":"TEST-002"}.
Новый документ: 201; дубликат: 200 с duplicate=true; конфликт/неверные данные: 400;
временная недоступность: 503. Пока доступ — локальная команда или SSH-туннель.
Не открывайте токен и endpoint в публичный интернет.

## Обмен с сайтом

Конфиг /etc/start-print-agent/config.json (root:start-print-agent, 0640).
Сайт предоставляет `/api/print-agent/v1/jobs`, `/events`, `/heartbeat`. Агент сам
подключается по HTTPS каждые 15 секунд; при сбое задержка растёт до 60 секунд.
Проверка сертификата обязательна, перенаправления запрещены. Порты LAN не открываются.

Настройки нового протокола:

```json
{
  "site_api_url": "https://spotsup.ru/api/print-agent/v1",
  "agent_id": "station-printer-1",
  "poll_token": "<отдельный общий секрет не короче 32 символов>",
  "poll_seconds": 15,
  "poll_url": "",
  "printing_enabled": false
}
```

Добавьте эти поля в существующий защищённый конфиг; не заменяйте весь файл и не
меняйте локальный api_token, путь БД или IP. Старый poll_url оставлен для обратной
совместимости, но включать его одновременно с site_api_url нельзя.
Постоянный database_id из таблицы meta локальной БД должен быть явно прописан на
сервере в PRINT_AGENT_DATABASE_ID. Потеря/замена БД требует ручной сверки очередей.

Документ, команда и событие подтверждения сохраняются одной SQLite-транзакцией.
Исходящие события остаются в event_outbox до accepted_event_ids от сайта.
Повтор GET, потеря ACK и перезапуск не создают новый чек. Сетевой reprint имеет
постоянный job_id команды и также идемпотентен. Локальная команда `start-print reprint`
остаётся ручной операцией: каждый её новый вызов означает новую попытку.

Кнопка «Напечатать отчёт» реализована в существующей админке сайта. Повторное обычное
нажатие открывает сохранённый снимок. Обновление сумм — явная новая редакция;
перепечатка — отдельное подтверждение с причиной и надписью ПОВТОР.
Статусы заказа кафе видны в его карточке. Реализация протокола: `site_protocol.py`.
Полный контракт и инструкция установки — в `../deploy/PRINT-PROTOCOL-DRAFT.md`
и `../deploy/PRINT-INTEGRATION.md` репозитория сайта.

## Завершение при подключении принтера

1. Подключить питание, бумагу и USB к Raspberry Pi; проверить lsusb и sudo lpinfo -v.
2. Убедиться в модели/ESC-POS и фактической ширине бумаги. Создать start-kitchen
   по обнаруженному USB URI, raw для готового ESC/POS, назначить default,
   printer-error-policy=stop-printer, отключить banner pages и sharing.
3. Проверить реальные растр, кириллицу, отрезчик, поддерживаемую команду звука.
4. Включить printing_enabled после проверки сохранённых заданий, перезапустить
   агент; проверить TEST-002 на бумаге, затем повторный submit без нового чека.
5. Проверить доставку нового заказа кафе и отчёта с сайта, статусы и повторное
   нажатие без дубликата. Старую тестовую очередь сначала просмотреть вручную.

## Проверка кода

```sh
cd /opt/start-print-agent
python3 -m unittest tests test_protocol -v
```
Тесты используют временную БД и имитацию CUPS; они не подтверждают работу бумаги.
