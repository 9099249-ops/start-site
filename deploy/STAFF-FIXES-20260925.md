# Исправления после проверки сотрудниками — 25.09.2026

Опубликовано на spotsup.ru в 22:03 МСК. Агент Raspberry Pi обновлён первым,
в 22:01 МСК. Данные заказов, остатки, закрытые смены и выплаты не мигрировались.

## Изменения

- Кнопка личной смены сохраняет подтверждение/ошибку на экране. Запоздавший GET
  не перезаписывает результат действия. Повтор после обрыва связи использует
  прежний идентификатор запроса; двойное нажатие блокируется. Для браузеров без
  `crypto.randomUUID` используется UUID на основе `crypto.getRandomValues`.
- Видимая кнопка «За день» открывает аренды за выбранную дату: все / на воде /
  возвращены. Учитываются переходящие через полночь аренды. Работают общий поиск,
  возврат из строки, детали и существующая правка администратора. Из истории
  можно сразу вернуться на экран «На воде».
- «Очистить корзину» удаляет блюда из черновика, «Новый заказ» сбрасывает также
  клиентские поля. Очистку можно отменить. Уже отправленные заказы не удаляются;
  сброс блокируется при незавершённой отправке с неизвестным результатом.
- В меню сотрудника показано доступное число порций и количество в корзине.
  Для вариантов показан верхний предел по варианту, для незаполненных остатков —
  соответствующая надпись. Сервер по-прежнему проверяет весь заказ и общий расход
  ингредиентов; меню не резервирует порции до оформления.
- Объединено получение «К столу / в лаунж». Место необязательно при оформлении,
  его можно назначить после заказа. Существующие QR/NFC остаются рабочими.
- Изменение места имеет проверку прав, версии и повторного запроса, сохраняется
  в истории и журнале, отправляется как уточнение в существующий Telegram.
  Сумма, состав, статус и списание со склада не меняются. Повторное сохранение
  того же места нового события не создаёт.
- Печать уточнения места: отдельный `LOCATION` с пустыми позициями и нулевой
  суммой, заметная надпись «НЕ НОВЫЙ ЗАКАЗ». Исходный чек неизменен, доставка
  уточнения защищена существующим механизмом дедупликации.
- Версии изменённых JS/CSS обновлены на всех использующих их страницах.

## Зарплата

По согласованию владельца существующая настройка распределения бонуса 5%
изменена с `equal` на `hours` через `WorkforceStore.saveSettings`, с записью
в финансовом журнале. Это настройка новых рабочих дней. Сохранённые настройки
25.09 и прежних дней не изменены. Текущий режим базы остаётся `fixed`, 2 500 ₽.
Для пропорционального расчёта базы за неполный выход ожидается ответ владельца:
сколько часов составляет полный выход за 2 500 ₽. Почасовая ставка не выдумана.
