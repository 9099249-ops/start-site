# Публикация и инфраструктура

Действует вместе с корневым `AGENTS.md`. Существующие README, конфигурации Nginx/systemd и специальные инструкции этой папки имеют приоритет для конкретных команд, путей и окружения. У проекта нет автоматической production-публикации через GitHub и нет обязательной сборки обычного сайта.

## Владение и разрешения

- GPT-6 отвечает за план выпуска, инфраструктуру, миграции, совместимость API и решение об откате. Luna собирает read-only сведения о версиях, службе, файлах и зависимостях. Luna-исполнитель может подготовить ограниченный пакет/документацию по плану, но не решает самостоятельно менять инфраструктуру или данные.
- Разрешение редактировать код, инструкции или отправлять commit/push не означает разрешения публиковать на рабочий сервер. Перед реальными изменениями проверить, что пользователь разрешил этот выпуск и среду. Если разрешение уже получено в текущей задаче, не запрашивать его повторно.
- Не исполнять `repair-access-stock.mjs`, `fill-cafe-recipes.mjs`, `enable-sale-bonus.mjs` и похожие утилиты как smoke test: они меняют бизнес-состояние. Новые сервисы, destructive operations, схемы БД и права доступа эскалировать GPT-6.

## Подготовка и проверка выпуска

1. Определить минимальный список файлов, зависимости и проверенный git diff; сверить реальные серверные версии. Сравнивать также содержимое, а не делать вывод о бизнес-различии только из хеша/переносов строк.
2. Прочитать применимые инструкции; проверить пути, текущую службу, окружение и совместимость. Не выводить секреты из env/config, токены и личные данные в отчёты.
3. До установки сохранить прежние файлы и согласованную резервную копию SQLite через backup API. Простая копия открытого файла SQLite не заменяет такую копию. Сохранять права доступа к резервным копиям и секретам.
4. Проверить пакет, его контрольные суммы, синтаксис и предпосылки установки; подготовить откат файлов. Потеря SSH-соединения не доказывает ни успех, ни неудачу: сначала проверить фактическое состояние.
5. Установить только разрешённые изменения, затем проверить службу, доступность нужных страниц/API и фактически обслуживаемые версии файлов. Проверка не должна создавать реальные заказы, списывать остатки, запускать реальные платежи или перепечатывать задания.
6. При сбое использовать согласованный откат. Не затирать рабочую БД резервной копией автоматически: после её создания могли появиться новые операции; восстановление данных требует отдельного решения GPT-6 и соответствующего разрешения.

Пути существующей службы определяет `start-site.service`: код `/opt/start-site`, база `/var/lib/start-site/bookings.sqlite`, окружение `/etc/start-site.env`, служба `start-site`. Перед использованием на другой среде проверять конфигурацию. Публикация сайта и установка на Raspberry Pi являются отдельными действиями.

В итоговом отчёте назвать фактически опубликованные файлы/версию, проверки, место резервной копии и ограничения. Не заявлять о публикации по одному успешному upload или push.
