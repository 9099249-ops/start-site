# СТАРТ: подключение печати

## Состояние на 25.09.2026

Реализация готова и проверена на отдельной локальной базе. **На рабочий сайт и
Raspberry Pi эти изменения пока не установлены.** SSH к Pi отклоняет ключ; владелец
выполняет добавление согласованного ключа через PuTTY. Прямое SSH-соединение с
сервером сайта не проходит обмен приветствием. Принтер ещё не подключён; физическая
печать, отрезка и звук не проверены. Это не отчёт о завершённой установке.

Владелец согласовал: Pi забирает задания, сайт получает подтверждения и статусы;
открытая смена — предварительный отчёт, закрытая — итоговый; выплаты только за
текущую или последнюю смену. **Общий итог кассы уже включает кафе + прокат.**

## Что изменено

- `server/print.mjs`: очередь, снимки отчётов, авторизация, журнал, API устройства.
- `server/server.mjs`: подключение модуля к существующему серверу и базе.
- `server/cafe.mjs`: задания NEW/ADD/CANCELLED в транзакции существующего заказа.
- `dist/admin/print-ui.js`, `print-ui.css`: кнопка, снимок, статусы, явный повтор.
- `dist/admin/app.js`, `operations.js`, `cafe.js` и соответствующие HTML: встраивание
  в существующие страницы. Кнопка отчёта — «Прокат → Ещё», рядом со сменой и кассой,
  а также `/admin/workforce/`. Статусы кафе — карточка заказа → история уведомлений.
- `dist/admin/desk.css`: перенос элементов старой шапки «Ещё», устраняющий
  горизонтальную прокрутку на узком экране.
- `start-print-agent/main.py`, `site_protocol.py`, `install.sh`: постоянные команды,
  исходящая очередь событий, подтверждения, heartbeat, шаблоны предварительного,
  итогового отчёта и повторной печати.
- `.env.example`, `deploy/start-site-https.nginx`, документация и тесты.

Таблицы сайта создаются идемпотентно при запуске: `print_documents`, `print_jobs`,
`print_events`, `print_audit`, `print_device`. Таблицы агента: `server_commands`,
`event_outbox`; `meta.database_id` создаётся один раз. Существующие заказы, смены,
начисления, платежи и локальные задания не удаляются и не пересчитываются миграцией.

Доступ: отчёты и ручной повтор — admin. Сотрудник кафе видит состояние печати своего
рабочего заказа через существующую авторизацию. Токен устройства не выдаётся браузеру.

## Подготовка установки

1. Сверить текущие версии файлов на сервере и Pi. Сохранить резервные копии изменяемого
   кода, защищённых конфигураций и обеих SQLite через SQLite backup (не копированием
   открытого файла без WAL). Копии с данными хранить только на соответствующем сервере.
2. Обновить файлы сайта, не заменяя `.env`, базу и опубликованный контент. Запустить
   серверные тесты в отдельном каталоге; проверить миграцию на копии базы. Внести
   только location `/api/print-agent/v1/` с лимитом 256k в действующий Nginx-конфиг,
   сохранить остальные правила; выполнить `nginx -t` перед reload.
3. Установить обновлённый агент командой `sudo sh install.sh` из его каталога.
   Скрипт сохраняет существующий `/etc/start-print-agent/config.json`, данные и IP.
   На Pi требуются Python 3, CUPS, python3-cups, Pillow и DejaVu Sans, уже установленные
   при первоначальной настройке. `printing_enabled` пока оставить false.
4. Получить постоянный идентификатор установленной БД агента локально на Pi:

```sh
sudo -u start-print-agent python3 - <<'PY'
import sqlite3
with sqlite3.connect('file:/var/lib/start-print-agent/queue.sqlite3?mode=ro', uri=True) as db:
    print(db.execute("SELECT value FROM meta WHERE key='database_id'").fetchone()[0])
PY
```

5. Сгенерировать отдельный случайный секрет минимум 32 символа. Передать его в
   защищённые серверные настройки без вывода в терминал, журналы или Git. Не использовать
   ключ Telegram, пароль admin или локальный api_token агента.

Сайт, `/etc/start-site.env`:

```dotenv
PRINT_ENABLED=true
PRINT_AGENT_ID=station-printer-1
PRINT_AGENT_DATABASE_ID=<идентификатор существующей БД Pi>
PRINT_AGENT_TOKEN=<отдельный секрет>
```

Pi, дополнительные поля существующего `/etc/start-print-agent/config.json`:

```json
{
  "site_api_url": "https://spotsup.ru/api/print-agent/v1",
  "agent_id": "station-printer-1",
  "poll_token": "<тот же отдельный секрет>",
  "poll_seconds": 15,
  "poll_url": "",
  "printing_enabled": false
}
```

Права файла Pi: root:start-print-agent, 0640. Существующие api_token, printer,
database, port, параметры ленты и логи сохранить. Перезапустить службы сайта и агента.
Проверить heartbeat и статус «Агент на связи · физическая печать отключена».

## Проверка после установки

- Запросы без токена отклоняются; неверный database_id — 409, автоматической перепривязки нет.
- Создать один явно тестовый отчёт, повторить нажатие: один серверный job_id,
  одна локальная попытка. Подтверждение `received` означает сохранение на Pi.
- Перезапустить агент: то же задание не размножается. Не терять event_outbox.
- Проверить заказ кафе и дозаказ на отдельной тестовой базе; не создавать фиктивные
  оплаченные заказы в рабочей кассе ради проверки.
- Перед включением физической печати просмотреть очередь, включая ранее сохранённый
  `TEST-002` и новые предварительные отчёты. Не включать без разбора накопленные задания.
- После подключения принтера проверить 80 мм, кириллицу, рубль, отрезку, звук и CUPS
  `printer-error-policy=stop-printer`. Только затем включать printing_enabled.

`PRINT_ENABLED=false` останавливает новые задания и обмен; уже полученные Pi задания
это не отменяет. Для остановки печати также выключить printing_enabled на Pi.
При откате оставить новые таблицы и файлы БД: удалять их или восстанавливать старую
базу поверх новых заказов нельзя. Не изменять database_id для обхода ошибки сопряжения.

## Проверки, выполненные локально

- `node --test server/*.test.mjs`: **157 / 157**, включая 18 тестов печати.
- `python -m unittest tests test_protocol -v`: **24 / 24**, включая 15 тестов протокола.
- Проверены одинаковый канонический JSON и SHA-256 между Node/Python, денежные единицы,
  текущая/последняя смена, вычет выплат, неизменяемый снимок, отдельные предварительный
  и итоговый документы, новая редакция и ручной повтор.
- Четыре независимых подключения к SQLite одновременно создают один отчёт.
- Проверены потеря ACK, перезапуск, старые/повторные события, неверный хеш, роли,
  переполненная очередь, откат заказа и склада при ошибке сохранения задания.
- Проверены обрывы CUPS, удержанная старая попытка, запрет её обхода повтором,
  некорректные документы, сохранение исходящих подтверждений до ACK.
- Полностью сохраняются допустимые 60 добавок, вариант и комментарий к блюду,
  а также длинный комментарий заказа вместе с местом получения.
- Полный локальный HTTP-обмен реального сервера с Python-агентом и имитацией CUPS:
  два документа → два задания, статусы пришли в админку; после рестарта дублей нет.
- В браузере: обычная кнопка, повторное нажатие, новая редакция, подтверждение
  ручной перепечатки, статус заказа кафе; ширины 320 и 390 px и POS 1280 px.
  Ошибок в консоли не обнаружено. На 320 px устранён найденный горизонтальный скролл.

Тесты используют временные данные и имитацию CUPS. Они не подтверждают бумажную
печать, доступность живого Pi или завершённое подключение к spotsup.ru.
