# Кафе СТАРТ — требования к печати

Зафиксировано 25 сентября 2026 года по запросу владельца. Это требования к реализации, а не отчёт о выполненной настройке.

## Оборудование и состояние

- Заказан POScenter RP-100USE, подключение к Raspberry Pi по USB.
- Лента 80 мм; русский текст, знак рубля, автоотрезка и звуковой сигнал при печати заказа. Проверить на реальном устройстве.
- Raspberry Pi доступен по текущему адресу 192.168.1.121. IP НЕ менять: пользователь отменил настройку 192.168.1.240.
- 25 сентября 2026 настройка возобновлена: установлен CUPS и Python-агент /opt/start-print-agent/, включены systemd и локальный API. Принтер ещё не доставлен, физическая печать и звук не проверены, очередь принтера не создана. Подробности — start-print-agent/README.md.

## Обязательные функции

1. Печать заказов кафе с сайта.
2. Кнопка «Напечатать отчёт» в админке сайта для выбранной смены.
3. Отчёт содержит:
   - дату смены;
   - общую сумму за смену по всем услугам, включая прокат и кафе;
   - список «кому сколько перевести»: получатель и сумма для каждого получателя.

Кнопка только формирует задание печати; не закрывает смену и не выполняет денежные переводы. Автоматическая печать по расписанию пока не запрошена.

## Основа реализации

- Два типа задания: cafe_order и shift_report, с отдельными шаблонами печати.
- Сайт рассчитывает финансовые итоги и распределение переводов по своим учётным данным; агент не рассчитывает их по истории чеков.
- Для отчёта сохраняется снимок данных выбранной смены. Источник данных и правила расчёта переводов нужно определить по существующей логике сайта либо уточнить у владельца. Не придумывать получателей, проценты и суммы.
- Уникальные идентификаторы заданий с разделением по типам. Повтор HTTP-запроса или повторное нажатие кнопки не создаёт дубликат печати того же отчёта. Повторная печать — отдельное явное действие с отметкой «ПОВТОР» и записью в журнале.
- SQLite, постоянная локальная очередь, состояния received / printing / printed / failed, автозапуск и восстановление systemd, ограниченные по размеру логи и health-check.
- Принятие задания CUPS не равно подтверждению выхода бумаги. Неопределённый результат после сбоя требует проверки; автоматическая повторная отправка не допускается. При восстановлении учитывать уже существующее задание CUPS.
- Доступ к кнопке и финансовому отчёту только авторизованным пользователям админки с соответствующими правами.
- Админка показывает статус задания; не сообщает «распечатано» только на основании принятия запроса.
- Реальное API сайта ещё не предоставлено. Сетевой интерфейс агента и аутентификацию согласовать с архитектурой сайта; не открывать незащищённый доступ извне.

## Что нужно для реализации в админке

- Расположение исходников или проект сайта «Кафе СТАРТ».
- Определение смены и источник суммы по всем услугам, прокату и кафе.
- Существующие правила и получатели распределения «кому сколько перевести»; порядок учёта возвратов, скидок и способов оплаты, если это ещё не реализовано на сайте.

## Проверка готовности

- Заказ кафе печатается с кириллицей, отрезкой и звуком.
- Кнопка «Напечатать отчёт» создаёт задание по выбранной смене.
- Дата, общая сумма и суммы по получателям совпадают с данными сайта.
- Повтор запроса не печатает дубликат; ручной повтор работает и отмечается в журнале.
- Очередь переживает отключение связи и перезагрузку; неопределённый результат не вызывает автоматический дубликат.
