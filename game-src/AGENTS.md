# SUP-игра: отдельный исходный проект

Действует вместе с корневым `AGENTS.md`. Сначала читать `README.md`, `package.json`, `DATA-LICENSE.md` и применимые сведения в `VERIFICATION.md`. Версии и конкретные команды определяют существующие инструкции; исторический отчёт не является новым прогоном.

## Работа моделей

- Luna находит поток между `src/main.ts`, модулями `src/game/` (`Simulation.ts`, `Traffic.ts`, `Renderer.ts`, `Controls.ts`, `Audio.ts`, `Score.ts`), конфигурациями/картой и тестами.
- Luna-исполнитель реализует ограниченные UI/CSS, локальные компоненты/багфиксы, тесты и механические изменения по плану. Архитектуру симуляции, новые зависимости, сервисы и многомодульные изменения решает GPT-6.
- Править исходники в этой папке, а не только готовый результат в `../dist/game/`. Перенос сборки на сайт является отдельной задачей в разрешённом scope, не автоматическим побочным эффектом локальной правки.
- Сохранять существующие правила управления, игровой логики и формат данных. Не перегенерировать карту, не выполнять импорт или обновление геоданных без необходимости; учитывать лицензию OpenStreetMap.

## Команды и проверки

Из `game-src/`, используя версию Node.js из существующего README (Node.js 24 подходит для общего окружения проекта):

```sh
npm ci
npm test
npm run build
npm run dev
```

Установка зависимостей нужна только если они отсутствуют/не соответствуют lock-файлу. `npm run build` проверяет TypeScript и собирает Vite в `game-src/dist/`. Не менять lock-файлы/зависимости как побочный эффект задачи оформления.

После изменения видимого поведения проверять управление, отображение и соответствующий сценарий на desktop/телефоне. Для запуска preview использовать существующий script в `package.json`. Финальный review и решение о достаточности проверок остаются у GPT-6.
