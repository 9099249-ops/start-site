# UX-аудит: настройка и запуск

## Состояние

Сбор реализован, но выключен по умолчанию. Production-сбор не включался, реальное 72-часовое окно не запускалось. Окно было запущено только на изолированном тестовом стенде. Сведений о реальной частоте действий сотрудников и выборке для сравнения пока нет.

Локальная фабрика изолированной БД находится в `reports/tools/ux-fixture.mjs`. Она использует системный Temp, тестовые заказы и аренды; внешние интеграции отключены. Для локального прогона с тестовой телеметрией из PowerShell в корне проекта:

```powershell
$env:UX_AUDIT_PORT='14943'
$env:UX_AUDIT_LOAD='1'
$env:UX_AUDIT_FIXTURE_TELEMETRY='1'
node reports/tools/ux-fixture.mjs
```

Этот флаг включает сбор только в экземпляре тестовой фабрики. Он не включает production-сбор и не является наблюдением за реальными сотрудниками. Без `UX_AUDIT_FIXTURE_TELEMETRY=1` fixture оставляет телеметрию выключенной. Не добавляйте в fixture production-базу, секреты или платёжные интеграции.

Браузерные материалы и прежние ограничения инструментальной проверки находятся в `reports/evidence/`; вымышленные данные из стенда не входят в поведенческий отчёт.

## Политика и данные

- `UX_AUDIT_ENABLED` должен быть явно равен `1`; по умолчанию сбор выключен. `UX_AUDIT_DIR` должен быть абсолютным приватным каталогом вне `dist`.
- Телеметрия ограничена перечисляемыми событиями и полями. Случайные краткоживущие идентификаторы связывают события внутри сессии/сценария, но не привязаны к логину сотрудника, заказу, клиенту или устройству. События не содержат персональных полей, свободного текста, содержимого DOM, поисковой строки, сумм, URL/query/hash или session replay.
- Сценарное событие `*_completed` означает создание заказа кафе или аренды, а не подтверждение оплаты или финансовое завершение. События не заменяют финансовый журнал.
- Файлы событий и агрегированный отчёт остаются в `UX_AUDIT_DIR`, не в публичном каталоге. Записи создаются с ограниченными правами доступа; защитите и резервное копирование этого каталога.
- Автоматическая очистка через 7 дней не реализована. Определите и утвердите срок хранения до включения сбора; не предполагайте, что файлы удалятся сами.

## Запуск окна

1. Выберите абсолютный каталог для приватных данных, например `/var/lib/start-site/ux-audit`. Он должен быть доступен пользователю процесса Node.js и находиться вне `dist`.
2. До включения сбора один раз запустите из корня репозитория от пользователя службы:

   ```sh
   node server/ux-audit.mjs --start /var/lib/start-site/ux-audit
   ```

3. После успешного создания окна задайте в окружении сервера `UX_AUDIT_ENABLED=1` и `UX_AUDIT_DIR` на этот каталог, затем перезапустите сервер. Если сбор не нужен, оставьте `UX_AUDIT_ENABLED=0` или удалите переменную. При включении с отсутствующим/повреждённым окном сбор отключается до перезапуска процесса.

Команда записывает начало и конец окна длительностью 72 часа. Повторный старт при ещё активном окне отклоняется. Не запускайте её, пока не согласованы уведомление сотрудников, условия сбора и срок хранения.

## Отчёт и расписание

На сервере с настроенной `BOOKING_DB` основной процесс вызывает сборщик раз в 60 секунд и также выполняет проверку сразу при запуске. Если сервер перезапускается во время окна, проверка продолжается; если срок окна истёк во время остановки, отчёт формируется при следующем запуске. Поэтому отдельная сессия Codex или постоянно работающий агент не нужны. Автономность не означает работу при выключенном сервере: отчёт появится не раньше следующего запуска процесса после окончания окна.

Для ручной проверки/генерации после окончания окна CLI имеет точный синтаксис:

```sh
node server/ux-audit.mjs --report /var/lib/start-site/ux-audit
```

До окончания окна команда сообщает, что отчёт ещё не готов. Готовый файл создаётся приватно по пути `<UX_AUDIT_DIR>/reports/ux-audit-72h.md`; не копируйте его в `dist`. Серверный tick выполняет ту же генерацию автоматически.

Отчёт содержит агрегаты по событиям и завершённым сценариям кафе/проката. Сценарии без пары корректных начала и завершения учитываются отдельно. Он не позволяет оценить «неиспользуемые» функции без знаменателя возможностей и не даёт частоту использования сотрудниками без реальной выборки. Малые выборки требуют осторожной интерпретации.

## Безопасный тестовый стенд

`reports/tools/ux-fixture.mjs` принимает `UX_AUDIT_PORT`, `UX_AUDIT_LOAD` и `UX_AUDIT_FIXTURE_TELEMETRY`. В режиме, заданном выше, порт `14943`, `UX_AUDIT_LOAD=1` заполняет только тестовую базу, а `UX_AUDIT_FIXTURE_TELEMETRY=1` создаёт отдельное временное окно телеметрии. Исходящие интеграции fixture отключены. Данные этого запуска не должны попадать в отчёт реальной смены.

Production-включение в рамках этой задачи не выполнялось. Для него нужно отдельное явное разрешение и операционная проверка приватного каталога, доступа к нему, уведомления сотрудников и срока хранения.
