# Прокат: компактный рабочий экран

Экран `/admin/` сохраняет существующие операции выдачи, оплаты,
ручного отплытия, продления и возврата. Изменения интерфейса не запускают
аренду по факту оплаты и не закрывают её по потере Bluetooth.

## Аккумуляторы

- Верхние карточки показывают катамаран, заряд каждого аккумулятора и оценку
  времени. Несколько аккумуляторов не усредняются: круг показывает минимальный
  заряд, работа — минимальное время, зарядка — максимальное время до зарядки всех.
- Зарядка определяется существующим состоянием BMS `charging` и положительным
  током. Время до полного заряда рассчитывается из остаточной и полной ёмкости.
  Если полная ёмкость не задана, она оценивается по остаточной ёмкости и SOC,
  только при SOC не менее 5%.
- Для зарядки учитываются доступные минутные измерения за последние пять минут.
  Эффективный ток не превышает текущий: при снижении тока прогноз не становится
  короче из-за более высокого тока в прошлом. История ограничена минутными
  точками, поэтому короткие перерывы внутри минуты могут не попасть в историю.
- Это приблизительное время, не обещание окончания зарядки: будущий спад тока
  заранее неизвестен. На устаревших данных, при потере BMS/ESP32, отсутствии
  ёмкости или остановке зарядки соответствующий прогноз не показывается.
- Обновление каждые 5 секунд при ожидающей отплытия связанной аренде, иначе
  каждые 15 секунд. При скрытой вкладке опрос останавливается.
- Подробности и прежние действия подтверждения датчика открываются нажатием
  карточки. Связь с арендой остаётся явной: одинаковый тип катамарана не
  идентифицирует физическое судно, автоматическая привязка была бы неоднозначна.
  В форме одиночной аренды электрокатамарана выбирается конкретное судно.

## Предложение отплытия по ESP32

- Используются существующие `battery_trips`, защищённый ingest BMS и операция
  `/api/admin/rental-depart`, без отдельной системы аренд.
- После наблюдаемого присутствия BMS уже после назначения аренды, при явном
  непрерывном отсутствии Bluetooth 15 секунд и продолжающихся сообщениях ESP32
  кнопка становится красной `Отплыли?`. Одного прохода времени без сообщений
  ESP32 недостаточно. Неоплаченная аренда не может запускаться по сигналу.
- Восстановление Bluetooth отменяет неподтверждённое событие. Устаревший сигнал
  и отключённая ESP32 не позволяют подтвердить сенсорный старт.
- Сотрудник подтверждает существующей кнопкой. Клиент передаёт только ID и
  revision события, а сервер проверяет связь с этой арендой и берёт сохранённое
  время разрыва. Запуск аренды и подтверждение события записываются атомарно.
  До подтверждения время аренды и деньги не изменяются.
- Обычная кнопка без сенсорного события запускает аренду от ручного нажатия.
- Новое поле прошивки `bmsDisconnectedAgeMs` — длительность разрыва по
  монотонному времени ESP32. Часы устройства не используются: uptime привязан
  к времени сервера. Повторные, устаревшие и задержанные пакеты не обновляют
  свидетельство присутствия. Состояние и revision сохраняются в SQLite.
- Прошивка 1.1.2 совместима, но без нового поля точное время разрыва неизвестно:
  используется первое полученное сервером сообщение об отключении. Для точного
  старта нужно обновление ESP32 на прошивку 1.1.3 с `bmsDisconnectedAgeMs`.
- Для аренды нескольких катамаранов одной записью сохраняется ручной запуск:
  сигнал одной BMS не должен запускать оплаченный срок всего комплекта.

## SMS

Исправлено принудительное переименование отправителя `SMS Aero` в `СТАРТ`.
Отправитель должен быть принят провайдером; произвольное название станции
не означает, что имя зарегистрировано. При выпуске проверять `sms/testsend`,
а не отправлять сообщения сотрудникам ради проверки.

Явный отказ провайдера по отправителю/номеру/авторизации сохраняется как
неповторяемая ошибка. Неопределённый результат отправки остаётся неопределённым
и не отправляется автоматически повторно. Старые просроченные напоминания
не восстанавливаются выпуском интерфейса.

## Проверки

Из корня, Node.js 24:

```sh
node --test server/battery-charge-estimate.test.mjs server/battery-state.test.mjs server/battery-control.test.mjs server/battery-trips.test.mjs server/sms-sender.test.mjs server/staff-sms.test.mjs server/staff-sms-settings.test.mjs
node --test server/rental-mockup-ui.test.mjs
node server/testing/rental-mockup-demo.mjs
```

Демонстрация использует временную SQLite, синтетические данные и заблокированные
внешние запросы. Не задавать ей production-секреты или рабочую базу.
Публикация: резервная копия SQLite через backup API, контроль исходных хешей,
точечная замена только проверенных файлов, перезапуск и проверка выданных
браузеру файлов. Рабочая БД не заменяется.
