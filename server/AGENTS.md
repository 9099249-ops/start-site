# Сервер: API, данные и бизнес-логика

Действует вместе с корневым `AGENTS.md`. Сначала читать локальный `README.md` и применимые документы предметной области. Доменные области находятся в одной папке: не создавать искусственную структуру ради агентных ролей.

## Карта для Luna

| Область | Начальные точки исследования |
| --- | --- |
| HTTP, запуск, конфигурация | `server.mjs`, `admin.mjs`, `README.md`, корневой `README.md` |
| Бронирование, календарь, прокат | `server.mjs`, `guard.mjs`, `calendar.mjs`, `admin.mjs`, `rental-actions.mjs`, `rental-pricing.mjs`, `aqsi-rental.mjs` |
| Кафе, POS, статусы, кухня, табло | `cafe.mjs`, `cafe-list.mjs`, `cafe-board.mjs`, `guest-bills.mjs`, `aqsi-cafe.mjs`, `CAFE-BOARD.md` |
| Платежи, касса, возвраты | `aqsi-pilot.mjs`, `aqsi-cafe.mjs`, `aqsi-rental.mjs`, `cash-ledger.mjs`, `refunds.mjs`, `../REFUNDS.md` |
| Сотрудники, смены, зарплата | `workforce.mjs`, `schedule.mjs`, `auto-shift.mjs`, `sale-bonus.mjs`, `tasks.mjs` |
| Склад, закупки и рецептуры | `inventory.mjs`, `cafe-stock.mjs`, `cafe-stock-links.mjs`, `cafe-coffee-stock-links.mjs`, `../dist/admin/purchase.js` |
| Клиенты и уведомления | `clients-export.mjs`, `sms.mjs`, `telegram.mjs`, клиентские данные в `admin.mjs`/`cafe.mjs` |
| Печать | `print.mjs`, `migrations/`, `../start-print-agent/`, `../deploy/PRINT-INTEGRATION.md` |

Это начальные точки, а не полный граф зависимостей. Luna прослеживает handler, проверку доступа, store/транзакцию, сохранённые поля, UI-потребителей, side effects и тесты. Учитывать `testing/`, `migrations/` и все использования изменяемого поля в соседних модулях и `dist/`.

## Владение изменениями

- GPT-6 принимает решения по БД/миграциям, API-контрактам, безопасности, бронированию, платежам, зарплате, конкурентным запросам и общей бизнес-логике. Не менять схему при запуске или порядок транзакций как побочный эффект небольшой задачи.
- Luna-исполнитель получает точный scope для локального багфикса, валидации, теста, небольшого рефакторинга или реализации уже определённого API. При необходимости изменить публичный контракт или любой чувствительный сценарий действует эскалация из корневого файла. Независимую проверку значимого изменения выполняет отдельный агент Luna, не автор реализации.
- Сохранять проверки роли, revision/requestId, идемпотентность, историю действий, атомарность денег/остатков и ограничения повторов. Ошибка/таймаут внешнего платежа не означает отсутствия списания.

## Связанные сценарии

- Кафе: различать заказ с сайта до оплаты, POS-предоплату, отложенный счёт гостя и быструю выдачу. Проверять `pendingKitchen`, `terminalPaidAt`, статусы, события печати, остатки, табло и клиентский экран. Наличные «в работу» не должны превращаться в уже выданную продажу.
- Прокат: проверять выдачу, возврат, продление, календарь, стоимость, доступность оборудования, оплату и историю клиента. Не делать независимые вычисления цены в интерфейсе вместо действующего контракта.
- Персонал: учитывать границы дня/времени, реальные интервалы работы, кассу, изъятия, закрытые расчёты и отчёты. Не пересчитывать закрытую зарплату или включать служебный логин `admin` в заработок. Остальные аккаунты с ролью администратора не исключаются автоматически.
- Склад: сохранять точные количества и единицы, отдельные товары/пиццы, историю приёма и списания. Рецептура, опция блюда и остаток связаны; отмена уже приготовленного блюда не всегда возвращает ингредиенты.
- Клиентский номер заказа остаётся представлением внутреннего ID. Связи БД и API-операции не переводить на циклический `displayNumber`.

## Проверки

Node.js 24; запуск и все команды ниже из корня репозитория, не из `server/`. Сервер использует встроенные HTTP/SQLite и не имеет отдельного npm-проекта.

```sh
node --test server/cafe-compose-ui.test.mjs server/aqsi-cafe.test.mjs server/cafe-board.test.mjs
node --test server/*.test.mjs
```

Первая команда является примером связанного набора для кафе; Luna выбирает реальные `*.test.mjs` под задачу. Для проката, кассы, смен и склада выбирать соответствующие тесты вместе с зависимыми сценариями. Полный набор нужен при широком влиянии или общей/финансовой логике. Не фиксировать в инструкциях историческое число тестов как текущую гарантию.

Тестовые БД и внешние сервисы должны быть изолированы. Запуск `server.mjs` с реальным `BOOKING_DB` может инициализировать/изменить состояние; это не способ read-only исследования. Не применять тесты, repair-утилиты и миграции к рабочей базе.
